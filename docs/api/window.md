状态：`implemented`（Rime 原生表面）。`list`（WinTitle 查询）、`active`、`info`、`controls`（WinGetControls/WinGetControlsHwnd）、`text`（WinGetText）、`exists`（WinExist）、`isActive`（WinActive）、`wait`（WinWait 家族条件等待）、`move`、`focus`、`close`、`kill`（WinKill）、`redraw`（WinRedraw）、`hide`、`show`、`minimize`、`maximize`、`restore`、`zorder`（WinMoveTop/WinMoveBottom）、`minimizeAll`/`minimizeAllUndo`（WinMinimizeAll/WinMinimizeAllUndo）、`setTitle`（WinSetTitle）、`setEnabled`（WinSetEnabled）、`setAlwaysOnTop`（WinSetAlwaysOnTop）、`setStyle`（WinSetStyle）、`setExStyle`（WinSetExStyle）、`setTransparent`（WinSetTransparent）、`setTransColor`（WinSetTransColor）、`setRegion`（WinSetRegion），以及 `groups`（GroupAdd/GroupActivate/GroupDeactivate/GroupClose，`rime:window` 的 `groups` 导出 + SDK `groups()` 门面）均有 TS binding、`windows.window.read`/`windows.window.write` capability 校验、`window-v1` contract（`contracts/schema/window-v1.schema.json`）与 native/slice 测试。读写接受 `deadlineMs`/`cancellationId`（`AbortSignal`）选项，deadline 过期与排队超时返回 `timeout` 错误码。全局窗口设置 `settings.window`（`SetTitleMatchMode`/`DetectHiddenWindows`/`DetectHiddenText`）同步读写，不经过 Action 队列。

快照即 WinGet 读族的承载面：`rect`（WinGetPos）、`clientRect`（WinGetClientPos）、`style`/`exStyle`（WinGetStyle/WinGetExStyle，无符号 32 位）、`enabled`（WinGetEnabled）、`alwaysOnTop`（WinGetAlwaysOnTop）、`minMax`（WinGetMinMax，-1/0/1）、`transparent`/`transColor`（WinGetTransparent/WinGetTransColor，未设置为 `-1`/`""`）、`region`（区域包围盒 `"left,top,right,bottom"`，未设区域为 `""`——**扩展字段**：AHK 无 WinGetRegion，非矩形区域经 `GetRgnBox` 报告包围盒）、`processPath`（WinGetProcessPath，读不到为 `""`）；`list` 的返回长度与首/末元素分别承载 WinGetCount、WinGetID、WinGetIDLast；`controls` 承载 WinGetControls（ClassNN）与 WinGetControlsHwnd（`id`，稳定 ID 而非裸 HWND），`text` 承载 WinGetText（`

核心类型使用稳定 `WindowId`、不可变 `WindowSnapshot` 和 `WindowQuery`。JS 不接收 `HWND`。查询、快照和等待走 Promise；纯字段访问同步。写操作生成 Action 并记录 Trace。目标消失时返回 `target_gone`（窗口已销毁，或 ID 属于上一个服务实例）；ID 形如 `[generation:32][sequence:32]`，进程内跨服务单调不复用（约束见 `docs/api/future-runtime.md`）。控件 `id` 走同一注册表（`WindowService::controls` 经 `registry->id_for(control)` 分配），复用 `WindowId` brand——Win32 子窗口即窗口，不另设 control id 类型。

## 执行模型

**写路径（Action）**：JS 构造 Action → Dispatcher 有界队列（入队决策 `ActionAccepted`/`ActionRefused` 进 Trace；同键共存的连续变更由 idempotency-key/同参数 key 合并，被合并方以 `cancelled:superseded by newer action` 拒绝，队列满为 `queue_full`）→ pump 执行 → Kernel（契约校验 → 取消检查 → 入口 deadline → capability → 执行器 → 执行后 deadline/取消复检）→ Executor（每次 UI 往返前重算剩余预算，含 `active` 目标解析；组动作以 `{kind:"group", id:"<组名>"}` 为目标、桌面动作用 `{kind:"desktop", id:"all"}`，二者都不解析窗口身份）→ UI lane → 快照结果。

- 执行后过期：结果改写为 `timeout`，消息声明 `side effects may have occurred`（副作用不可撤销，调用方据此判断）。
- 执行后取消：同理改写为 `cancelled` 并声明副作用可能已发生。
- 取消边界：仅在「执行前 / 往返之间 / 执行后」检查；已进入的 Win32 调用（如 `SendMessageTimeoutW`）只能等其超时，不被强行打断。

**读路径（观察，豁免于 Action Kernel）**：`list`/`active`/`info`/`controls`/`text`/`exists`/`isActive`/`wait` 经同一 capability 策略校验后直调 `WindowService`，**不产生 `ActionStarted/ActionFinished` Trace，也没有 Kernel 级 deadline**；`deadlineMs` 在请求构建时折算为该次 UI 阶段的等待预算——对 `wait` 则是**整个等待预算**（到期拒绝 `timeout`）。这是观察（Snapshot/Query）与变更（Action）的语义分界，属文档化豁免，不是遗漏。

**设置路径（同步状态，豁免于 Action Kernel）**：`settings.window` 的四个属性与三个 `set*` 方法在 JS 线程同步读写 `WindowService` 原子状态——**不入队、不产生 Action Trace**；`get` 校验 `windows.window.read`、`set` 校验 `windows.window.write`（先解析/校验值、再查能力，均同步抛出 `TypeError`）。每次**实际变化**记录一条 `kind=StateChanged`、`subject=window.settings`、`detail="key before -> after"` 的 Trace，无变化的 set 返回当前值且零 Trace。

## 语义细则

- **前台选择**：只用 `active: true`。历史上的 `title == "A"` 魔法短路已删除——不存在无法按字面匹配的标题。
- **`active` 的两层含义**：① **读**——`rime:window` 模块与桥接口的 `windows.active(options?)` 返回当前前台窗口快照或 `null`（WinActive 的快照形态，读路径不入队）；SDK 门面不暴露读方法，前台过滤用 `list({ active: true })`（`WindowQuery.active`）。② **动作入口**——SDK `Window.active()` 返回惰性句柄 `ActiveWindowRequest`（`.move/.zorder/.focus/.close/.kill/.redraw/.hide/.show/.minimize/.maximize/.restore`），目标串 `active` 在动作执行时重新解析前台，结果为操作后快照。同名不同层：前者取快照，后者是写动作的 fluent 入口。
- **`focus`**：先 `SW_RESTORE`，再走共享的取前台阶梯 `acquire_foreground()`（`engine/win32/src/window_foreground.cpp`，与 `setAlwaysOnTop` 的前台获取同一实现）：① `SetForegroundWindow`；② 拒绝则 `AttachThreadInput` 挂到**当前前台线程**的输入队列后重试并立即摘除；③ 仍拒则 AHK `WinActivate` 同款**裸 Alt 轻点**（使本进程成为最后输入事件所有者）后再试。判定以 `GetForegroundWindow()` 回读为准，不采信 `SetForegroundWindow` 的返回值（该函数可能报失败而窗口其实已前置）。三档全拒才返回 `ExecutionFailed`，消息含 `foreground lock`；`ForegroundRun` 枚举记录是哪一档赢下前台，但 `WindowService` 尚未接入 `TraceSink`，因此 `docs/AHK-TS-WINDOWS-API-DESIGN.md` 要求的"逐次记录每个尝试"仍未落地——该缺口作为遗留项记在 `docs/AHK99-IMPLEMENTATION-PLAN.md`。
- **大小写**：`title` 在所有模式下**大小写敏感**（AHK 规则：WinTitle 全模式敏感，唯一例外是 RegEx 模式的 `i)` 选项前缀）；`ahkClass` 大小写不敏感（ahk_class 自 AHK v2.1 起如此）；`ahkExe` 为 ASCII fold（规则见 `window.cpp` 的 `fold_ascii` 注释），非 ASCII 部分按精确字节比较。
- **`matchMode`**：`startswith`（1）、`contains`（2，默认）、`exact`（3）、`regex`（4）；查询未给出 `matchMode` 时解析全局 `settings.window.titleMatchMode`。`regex` 模式将 `title`（或开启时的 `ahkClass`/`ahkExe`）按 AHK 正则编译：支持 `i)` 选项前缀；`m)`/`s)`（multiline/dotall）与未知字母同步抛 `Unsupported`，坏正则与空模式同步抛 `InvalidContract`——都不入队。`includeHidden` 缺省时解析全局 `settings.window.detectHiddenWindows`；无标题窗口始终被过滤。
- **全局设置**：`settings.window` 暴露 `titleMatchMode`（`"1"|"2"|"3"|"RegEx"`）、`titleMatchModeSpeed`（`"Fast"|"Slow"`）、`detectHiddenWindows`、`detectHiddenText` 四个属性与 `setTitleMatchMode`/`setDetectHiddenWindows`/`setDetectHiddenText` 三个方法；`set*` 返回前值（AHK return-previous 契约），`setTitleMatchMode` 接受模式串或 `"Fast"|"Slow"`（分派到速度旋钮）。默认：`"2"`、`"Fast"`、`false`、`false`。
- **`ahkId`**：正整数（number 或数字字符串），经 `from_chars` 严格解析，拒绝溢出与非数字。
- **`wait`（WinWait 家族）**：`until` ∈ `exists`（WinWait，成功返回目标快照）/ `active`（WinWaitActive，快照）/ `closed`（WinWaitClose，`null`）/ `notActive`（WinWaitNotActive，`null`；匹配不存在即视为满足，是 `active` 的逻辑否定）。`deadlineMs`（默认 5000）是整个等待预算，到期拒绝 `timeout`；**一处刻意偏离**：AHK `WinWait*` 缺省无限等待，Rime 默认 5000ms 防悬挂（显式 `deadlineMs` 按预算放宽）；`cancellationId` 触发拒绝 `cancelled`。实现为 25ms 调度器轮询 + worker lane 单次求值（`WindowService::evaluate_wait`）——**不阻塞任何线程**；窗口事件（WinEventHook）唤醒是后续优化，当前以轮询承担事件可见性。`until` 值非法时同步抛 `TypeError`（循环根本不启动）。
- **`move`（WinMove）**：双形态，`windows.move(target, position, options?)`。① 命名 placement：`"left"|"right"|"top"|"bottom"|"full"`，按主监视器工作区对半/整屏（Rime 扩展形态）；② 坐标 rect `{x?, y?, w?, h?}`（AHK WinMove 的 X/Y/Width/Height）：至少一个字段、整数、`w`/`h` ≥ 1、`x`/`y` 为屏幕坐标（多显示器允许负值），**省略字段保持当前值**（AHK 空参数规则），先 `GetWindowRect` 补齐再单次 `SetWindowPos`（最小化先 `SW_RESTORE`），窗口不经过中间形态。两形态互斥；空 rect、非整数/越界字段、`{position, rect}` 同给由 executor 拒绝 `invalid_contract`，入队前同步校验（非串/非对象、`w:0`、分数坐标、空对象同步抛 `TypeError`）。结果返回操作后快照，detail 记录 `window moved to <placement>` 或 `window moved to rect(x=.., ..)`。
- **`zorder`（WinMoveTop/WinMoveBottom）**：`windows.zorder(target, "top"|"bottom", options?)` → `SetWindowPos(SWP_NOMOVE|SWP_NOSIZE|SWP_NOACTIVATE)` 到 `HWND_TOP`/`HWND_BOTTOM`——不移动、不缩放、不激活（AHK 注释：缺 `SWP_NOACTIVATE` 时窗口经常不动）；`target` 接受 id 或 `"active"`，结果返回操作后的快照，失败为 `execution_failed`（含 win32 error）。**WinActivateBottom** 不是独立动作：`list()` 保持 `EnumWindows` 的自上而下 z 序，激活查询的**最后一个**匹配（`windows.focus((await windows.list(q)).at(-1).id)`）即 AHK 的语义（`DetermineTargetWindow(..., aBottom)` 取最后匹配）；**WinGetPos** 同理由快照 `rect`/`clientRect` 承载（见上）。
- **`kill`（WinKill）**：AHK `Util_WinKill` 同源——先 `SendMessageTimeout(WM_CLOSE, SMTO_ABORTIFHUNG)`，等待上限 500ms（并受动作 deadline 约束）；送达（或窗口已消失）即结束，超时/未送达则 `OpenProcess(PROCESS_TERMINATE)` + `TerminateProcess`。**一处刻意偏离**：目标 pid 是运行时自身时拒绝执行终止回退并返回 `execution_failed`（`refusing to force-terminate the runtime's own process`），不复制 AHK 的自杀路径。结果与 `close` 一致取关闭前快照。
- **`redraw`（WinRedraw）**：`InvalidateRect(NULL, TRUE)` 仅入队重绘，**不**调用 `UpdateWindow`（AHK 注释：强制立即 `WM_PAINT` 可能不合时宜）；`WM_PAINT` 由属主自己的泵处理，结果为无变化的快照。
- **`setTitle`/`setEnabled`/`setAlwaysOnTop`（WinSetTitle/WinSetEnabled/WinSetAlwaysOnTop）**：均为 `windows.window.write` 动作，结果返回操作后快照。`setTitle(id, title)` 写窗口标题；`setEnabled(id, value)` 中 1 启用、0 禁用、-1 切换，越界拒绝 `invalid_contract`；`setAlwaysOnTop(id, value?, options?)` 缺省=1 置顶，-1 按当前 `WS_EX_TOPMOST` 位反转，0 清除。**topmost 的前台权限**：Windows 只在调用进程持有 `SetForegroundWindow` 权限时才真正执行 `SetWindowPos(HWND_TOPMOST)`，否则**静默不生效**（MSDN SetWindowPos）；服务读回 `WS_EX_TOPMOST` 校验，未生效时取回前台（必要时先发 AHK `WinActivate` 同款裸 Alt 轻点以解除前台锁）、重试一次并尽力恢复原前台，仍不生效返回 `execution_failed`（`topmost state did not take ...`）——因此被前台锁拒绝时可能有一次窗口激活闪现。入队前同步校验：`title` 非串抛 `TypeError`；executor/服务层对缺 `title`、越界 `value` 拒绝 `invalid_contract`。
- **`setStyle`/`setExStyle`/`setTransparent`/`setTransColor`/`setRegion`（WinSetStyle/WinSetExStyle/WinSetTransparent/WinSetTransColor/WinSetRegion）**：均为 `windows.window.write` 动作，结果返回操作后快照。`setStyle(id, change)`/`setExStyle(id, change)` 用 AHK 变更串语法：`+N` 加位、`-N` 去位、`^N` 翻转、裸 `N` 整体替换（N 为十进制或 `0x` 十六进制，≤0xFFFFFFFF，空串/坏格式拒绝）；服务读回校验（uint32 防 `WS_POPUP` 符号扩展）、无变化即成功，配 `SWP_FRAMECHANGED|SWP_NOMOVE|SWP_NOSIZE|SWP_NOZORDER|SWP_NOACTIVATE` + `InvalidateRect` 失效非客户区。`setTransparent(id, value)` 中 0..255 置 `WS_EX_LAYERED`+`LWA_ALPHA`，-1 丢弃 `WS_EX_LAYERED`（AHK "Off"，alpha 与颜色键被 OS 一并遗忘），越界拒绝。`setTransColor(id, value)` 接受 `""`/`"off"` 清除颜色键、`RRGGBB`/`0xRRGGBB` **恰好 6 位 hex**（HTML 颜色名明确不做——刻意偏离 AHK），可选 `" <0-255>"` 后缀同设 alpha，省略 flag 时清 `WS_EX_LAYERED`。入队前同步校验：`change`/`value` 类型不符或透明度越界抛 `TypeError`；executor/服务层对坏变更串、越界透明度、坏颜色语法拒绝 `invalid_contract`。
- **`setRegion`（WinSetRegion）**：`setRegion(id, value = "", options?)` 用 AHK 选项串构形：`<x>-<y>` 坐标对（首对锚定形状，额外顶点构成多边形）+ 字母选项 `E`（椭圆）、`R`/`R<rrw>-<rrh>`（圆角矩形，默认 30x30）、`W<宽度>`/`Wind`（宽度或 WINDING 填充）、`H<高度>`（宽高为相对尺寸，服务端换算为右/下边），数字为带符号十进制；`""` 恢复正常区域（`SetWindowRgn(NULL)`）。形状选择顺序与 AHK 一致：椭圆 → 圆角 → 矩形（宽高齐备）→ 多边形；**刻意收紧**：椭圆/圆角缺宽高、少于三个顶点的多边形与超过 2000 点在契约层拒绝（AHK 放行到 Win32 层报错）。成功路径 OS 接管 `HRGN` 所有权（失败时我们 `DeleteObject`）；结果快照的 `region` 字段（包围盒 `"left,top,right,bottom"`，未设为 `""`）是 AHK 没有的扩展读回，GDI 对椭圆/圆角的远边取整会在包围盒上表现为右/下各小 1（观察行为）。入队前同步校验：`value` 非串抛 `TypeError`；executor/服务层对坏选项串拒绝 `invalid_contract`。
- **`minimizeAll`/`minimizeAllUndo`（WinMinimizeAll/WinMinimizeAllUndo）**：`windows.minimizeAll(options?)`/`windows.minimizeAllUndo(options?)` → UI lane `FindWindowW(L"Shell_TrayWnd")` 找到任务栏后 `PostMessageW(WM_COMMAND, 419/416)`（与 AHK 同源），**fire-and-forget**：不在 UI lane 同步等待桌面效果（同步等待会死锁回本进程消息泵），效果由 shell 异步处理；任务栏不存在或投递失败返回 `execution_failed`（含 win32 error）。目标为专用桌面目标 `{kind:"desktop", id:"all"}`（不解析窗口身份），`kind`≠`desktop` 或 `id`≠`all` 拒绝 `invalid_contract`（Win32 调用前）。结果 value 为空对象，detail 为 `"all windows minimized"`/`"all windows restored"`。观测注意：shell 的最小化遍历**跳过无边框窗口**（`WS_VISIBLE`-only 样式），416 只恢复 419 造成的小化（测试以 `WS_OVERLAPPEDWINDOW` 专用 victim 轮询观测，刚创建的窗口先短暂等待首次显示再投递，undo 无条件先于断言执行保证失败也不把桌面留在小化状态）。
- **`groups`（WinGroup 家族）**：`rime:window` 的 `groups` 导出 + SDK `groups()` 门面，四者均为 `windows.window.write` 动作（目标 `{kind:"group"}`，接受 `deadlineMs`/`cancellationId`）。`add(name, query, options?)`（GroupAdd）按精确四字段去重、缺组即建、返回规格计数；`activate(name, options?)`（GroupActivate）循环激活成员（`reverse` 从最近成员开始；缺组**创建后**因无成员返回 `null`，AHK 的 create-if-missing）；`deactivate(name, options?)`（GroupDeactivate）激活合格的非成员（可见、非顶层置顶/无激活、非裸工具窗、无属主、非桌面），缺组拒绝 `invalid_contract`（AHK 参数错误）；`close(name, mode?, options?)`（GroupClose）`""` 关闭前台成员后激活下一成员（Windows 已自动提升下一成员时停在该处）、`"reverse"` 反向、`"all"` 关闭全部成员且不激活，缺组与未知 `mode` 拒绝 `invalid_contract`。组注册表与访问轮换状态（cap 500）活在 UI lane 的 `WindowService` 内，无锁、进程级；成员匹配复用查询语义（全局 `matchMode`/`detectHiddenWindows` 参与）；空 query 规格被同步拒绝（AHK 容忍占位空规格，Rime 视为契约错误）；结果无目标时为 `null`（对齐 `active()`/`wait()`），激活被前台锁拒绝时为 `execution_failed`，`close('all')` 的计数不受焦点影响。

必须逐项覆盖的 AHK 函数（研究清单；逐函数状态以 `compatibility-matrix.md` 为准）：`WinActivate`、`WinActivateBottom`、`WinClose`、`WinGetAlwaysOnTop`、`WinGetClass`、`WinGetClientPos`、`WinGetControls`、`WinGetControlsHwnd`、`WinGetCount`、`WinGetEnabled`、`WinGetExStyle`、`WinGetID`、`WinGetIDLast`、`WinGetList`、`WinGetMinMax`、`WinGetPID`、`WinGetPos`、`WinGetProcessName`、`WinGetProcessPath`、`WinGetStyle`、`WinGetText`、`WinGetTitle`、`WinGetTransColor`、`WinGetTransparent`、`WinHide`、`WinKill`、`WinMaximize`、`WinMinimize`、`WinMinimizeAll`、`WinMinimizeAllUndo`、`WinMove`、`WinMoveBottom`、`WinMoveTop`、`WinRedraw`、`WinRestore`、`WinSetAlwaysOnTop`、`WinSetEnabled`、`WinSetExStyle`、`WinSetRegion`、`WinSetStyle`、`WinSetTitle`、`WinSetTransColor`、`WinSetTransparent`、`WinShow`、`WinWait`、`WinWaitActive`、`WinWaitClose`、`WinWaitNotActive`、`GroupAdd`、`GroupActivate`、`GroupClose`、`GroupDeactivate`、`SetTitleMatchMode`、`DetectHiddenWindows`、`DetectHiddenText`。

验收必须覆盖 WinTitle 解析、隐藏窗口、前台激活拒绝、窗口销毁竞态、超时取消、队列关闭和稳定 ID。

## 偏差与不实现项（报告口径）

- **`SendMessage` / `PostMessage`（含一切"脚本指定 msg/wParam/lParam 投递给任意窗口"的形态）：不实现，按政策裁剪。** 依据是三条同口径的既定条文——[`future-runtime.md`](./future-runtime.md) §10：「裸句柄、线程 ID、COM 指针、窗口过程、Hook 地址、任意 DLL 调用、任意内存读写、**未审计消息发送**、内部调度队列和 Native 对象指针不进入标准 TS API」；`design-review.md:148`：标准库不暴露「……任意 `DllCall/ComCall` 和**未审计的 SendMessage**」；`ts-windows-model.md:89` 同句英文（"…or unaudited `SendMessage`"）。因此 coverage 台账两行应由 `contract-only` 改判 `unsupported-by-policy`：`SendMessage`（`domain=input`，`tsModule @rime/input`）与 `PostMessage`（`domain=runtime-language`，`tsModule @rime/window`）同属一个消息发送面，条目统一落本页；`compatibility-matrix.md` 两行同步。
  - 本页已有的 Win32 消息使用**不构成**该面：消息与参数全部由 runtime 自选，脚本只能表达结构化意图、不能指定 `msg`/`wParam`/`lParam`，且从不持有 `HWND`（只持稳定 `WindowId`）——`close`/`kill` 的 `SendMessageTimeoutW(WM_CLOSE)`（`window.cpp:669`/`:717`，kill 上限 500ms 同 AHK `Util_WinKill`）、`getText` 的 `WM_GETTEXT`/`WM_GETTEXTLENGTH`（`window.cpp:438`/`:445`，`SMTO_ABORTIFHUNG`）、`minimizeAll`/`minimizeAllUndo` 的 `PostMessageW(WM_COMMAND, 419/416)`（`window.cpp:804`），以及 `ui_thread.cpp:295` 那个只作唤醒的 `PostMessageW(kTaskMessage)`。这也是 `window.md` 承载本条的原因：消息使用收在窗口域，而通用发送面被裁掉。
  - 替代路径：① 结构化 Action——要改窗口状态就用本页写族（`move`/`focus`/`close`/`kill`/`setTitle`/`setStyle`/`setRegion`/…），全走 `Context → Intent → Action IR → Action Kernel`，可检查、可 Trace、可取消；② UIA automation（`automation.find`/`read`/`invoke`）——控件语义层操作，不经窗口消息；③ 确需进程外任意消息的场景走隔离插件与版本化 token（计划 §0.3，`future-runtime.md` §10 的收口）。
  - 该判定同时撤销 [`runtime-language.md`](./runtime-language.md) §5 原先给 `PostMessage` 排的 M7（Win32 消息层）档期。
  - 登记缺口：`runtime-language.md` §1 既定规则要求 `unsupported-by-policy` 能指到 [`stdlib.md`](./stdlib.md) §5 的条目，而 §5 六条里没有逐字的「消息发送」（最接近的是第 1 条裸 `HWND` 与第 2 条消息泵细节，均非同一件事）；本条权威实为 `future-runtime.md` §10。建议在 §5 追加一条「未审计的窗口消息发送（`SendMessage`/`PostMessage`）」，或放宽该规则——`stdlib.md` 不在本轮可改文件内，故未改。
